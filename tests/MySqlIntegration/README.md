# Интеграция с выделенной локальной MySQL

**Меняет данные только в базе test на 127.0.0.1:3306, аккаунт root. Запускать только с разрешения владельца этой тестовой базы.** Нельзя использовать для рабочей БД. Приложение/Program.Main/фоновые службы не запускаются; модель и провайдер StoreCMS не изменяются.

Используются настоящий CMSDatabase, EF Core/Pomelo 2.2, преобразование моделей, уникальность имён, журналирование и исходные операции с чанками/изображениями. HTTP-контекст и IHostingEnvironment настроены для теста; файлы размещаются в отдельной scratch-папке. Нужен runtime ASP.NET Core 2.2 (проверено на 2.2.8), SDK и кеш исходных пакетов.

Пароль вводится скрыто в интерактивной консоли либо читается только в память из JSON через `--credential-config <путь>`. Формат файла: раздел DbSettings с ConnectionString, содержащим root и пароль. Хранить такой файл вне репозитория, ограничив доступ. Остальные параметры строки не используются: endpoint и база жёстко заданы в коде теста. Полная строка, параметры SQL и необработанные сообщения исключений не выводятся. Секрет не передавать значением аргумента команды.

Сборка из корня репозитория (офлайн, пакеты должны быть в кеше):

```powershell
dotnet restore tests/MySqlIntegration --configfile tests/MySqlIntegration/NuGet.Config -p:RestoreFallbackFolders="$env:USERPROFILE/.nuget/packages"
dotnet build tests/MySqlIntegration --no-restore
dotnet tests/MySqlIntegration/bin/Debug/netcoreapp2.2/MySqlIntegration.dll --preflight
```

При фактической проверке использовалась отдельная копия проекта приложения через свойство ProductionProject и внешний OutputPath, чтобы не перезаписывать рабочие результаты сборки.

Режимы (можно добавить --credential-config с путём к приватному файлу):

- `--preflight`: только соединение с локальным сервером, версия и наличие test; без создания контекста и записей.
- `--inspect`: только метаданные таблиц/кодировок test и полей ConnectedUsers.
- Без режима: создаёт test при отсутствии, подтверждает SELECT DATABASE(), затем запускает проверки. Создание CMSDatabase вызывает EnsureCreated.
- `--recreate-legacy-charset`: **удаляет и пересоздаёт только подтверждённую test** с utf8/utf8_general_ci, затем выполняет проверки. Не применять без разрешения на пересоздание.
- `--verify-clean`: только чтение количества строк шести затрагиваемых таблиц; ожидает пустую базу после прогона на свежей схеме.

Проверки создают записи с уникальным префиксом; в finally удаляются записи этого прогона и его временный каталог. Схема остаётся. При аварийном завершении процесса возможны остатки; не удалять чужие данные автоматически. Параллельные запуски самого набора не предусмотрены.

## Результат 2026-10-15

MySQL 8.0.40, ASP.NET Core runtime 2.2.8. Первый запуск на стандартной utf8mb4_0900_ai_ci остановился с MySQL 1071: составной индекс ConnectedUsers по четырём varchar(255) превышает 3072 байта. Схема была создана частично. После подтверждения test пересоздана с utf8 (utf8mb3); код приложения не менялся.

**19 проверок прошли:** подключение и создание схемы; добавление чанка; перегенерация зависимого шаблона, чанка и блока товара; изменение содержимого; переименование и повторное чтение; существующее поведение старых маркеров; обратное переименование; 20 параллельных рендеров вложенных условий с разными реальными контекстами; уникальные имена; удаление производных изображений; переименование и повторное чтение метаданных изображений; удаление чанка и журналирование. После очистки Chunks/Templates/Images/Users/UserTypes/AdminPanelLogs содержат по 0 строк.

Переименование чанка не переписывает старые маркеры в исходном тексте родителей: проверено как текущее поведение, не исправлено тестом. Результат не доказывает совместимость создания схемы с utf8mb4. Отображение Razor в браузере, HTTP-авторизация и одновременная публикация одного файла не проверялись.
