# Регрессии E0.1 / E0.2: публикация и условия Razor

## E0.2 — F01/F04 независимого аудита, 20.10.2026

Команды файлового набора ниже сохранены. На Windows 2.2.8 и 10.0.13 усиленный набор прошёл: 44 024 / 26 640 утверждений, 43 692 / 26 308 полных чтений. Количество непрерывных чтений зависит от планировщика; по 128 чтений подтверждены явными сигналами внутри измеренного интервала 128 вызовов обновления. Первый запуск в sandbox не смог выполнить MoveFileExW (код 5); окончательные прогоны выполнены вне sandbox.

Доказательства конкуренции:

- CountdownEvent подтверждает готовность всех 32 потоков; первый callback удерживает Gate, основной поток дожидается Users=32 (включая 31 ожидающего). Счётчик активных callbacks не допускает двух одновременных входов.
- Для отдельного второго writer сигнал подтверждает старт вызова, затем проверяются Users=2 и WaitSleepJoin именно этого потока. До освобождения первого writer callback второго не исполняется, а запись другого пути полностью завершается. После освобождения завершаются оба writer общего пути, запись реестра удаляется.
- AutoResetEvent запрашивает и подтверждает реальное чтение на каждой из 128 итераций. Подтверждение выставляется после чтения и проверки полной допустимой версии. Монотонные Stopwatch timestamps первого/последнего подтверждённого чтения проверяются внутри границ всего цикла обновления. Дополнительный непрерывный читатель проверяет полные версии; после цикла проверяется точная последняя версия. Перекрытие отдельных системных вызовов rename/read не утверждается.

Двойной отказ (Windows): final=OLD; callback ставит своему temporary ReadOnly и выбрасывает IOException-маркер из отдельного метода. File.Delete действительно отказывает. Проверяются тот же объект/тип/сообщение и первоначальный стек, OLD, освобождение реестра и запись из следующего потока. Отдельное исключение cleanup со стеком доступно в `Exception.Data["StoreCMS.RazorPublication.CleanupException"]`, путь остатка — в `Exception.Data["StoreCMS.RazorPublication.TemporaryPath"]`. Остаток и чужой temporary не затрагиваются следующей записью; тест сам снимает атрибут и удаляет только собственный остаток. Это структурированная диагностика, без добавления файлового логгера. Catch-фильтр production-кода не перехватывает единственную ошибку cleanup.

Для повторного HTTP-прогона в новой копии стенда поддерживаются необязательные переменные `STORECMS_RAZOR_HOSTS` (каталог с shared/Production, source-manifest.json, evidence и published10/22) и `STORECMS_RAZOR_RESULTS` (каталог результатов). Без них сохраняются прежние пути. E0.2 использовал `work/e02-razor/hosts` и `work/e02-razor`; прежние материалы E0/E0.1 сохранены. Пример после подготовки и publish копии:

```powershell
$env:STORECMS_RAZOR_HOSTS = "$PWD/work/e02-razor/hosts"
$env:STORECMS_RAZOR_RESULTS = "$PWD/work/e02-razor"
python tests/RazorPublicationRegression/check-hosts.py
python tests/RazorPublicationRegression/check-imports.py
```

Свежие HTTP-результаты E0.2: **63 PASS / 1 FAIL** из 64, imports — 2 PASS. 39 production-копий сверены по SHA-256; девять прежних HTML и CR/LF-эталоны совпали на двух runtime. В HTTP-гонке .NET 10 все 32 записи успешны, 511/512 чтений целые, одно — 500 с IOException/sharing violation при PhysicalFileInfo.CreateReadStream в Razor Runtime Compilation. На 2.2: 32 записи и 512/512 целых чтений PASS. Ошибка сохранена в `work/e02-razor/results.json`, `evidence/51870/race-reads.json`; отсутствие HTTP 500 не подтверждено. Причина/production-применимость требуют отдельной оценки; Runtime Compilation не менялся. Эта проверка HTTP не заменяет файловые доказательства F04.

F02/F03 независимого аудита — прежние открытые и отложенные дефекты (Unicode-разделители и Counter внутри условия). Они отличаются от исправленных ранее E0-F01/E0-F02. Linux **NOT TESTED**. БД и пользовательский Storage не используются. Отчёт: `output/pdf/StoreCMS_E0.2_F01_F04_2026-10-20.pdf`.

## Файловый набор

Из корня репозитория:

```powershell
dotnet run --project tests/RazorPublicationRegression -f netcoreapp2.2 -p:NuGetAudit=false
dotnet run --project tests/RazorPublicationRegression -f net10.0 -p:NuGetAudit=false
```

Нужны соответствующие runtime и SDK для сборки. Используется только собственный каталог `StoreCMS-E01-<GUID>` в системном temp; finally удаляет его. В ограниченном sandbox может потребоваться разрешение на файловые операции.

Сценарии: создание, замена, UTF-8 без BOM, 100 последовательных и 32 конкурентные записи; независимость разных путей при удержании блокировки; эквивалентные полные пути и регистр Windows; отказ после закрытия временного файла и до публикации; реальный отказ публикации при запрещающем Windows-дескрипторе; сохранность прежней версии и чужого `.tmp`; отсутствие собственного мусора; освобождение реестра блокировок; 128 обновлений при непрерывном чтении. Читатель открывает файл с `FileShare.ReadWrite | FileShare.Delete`, каждое чтение сверяется с полным набором допустимых версий. Тестовая точка - internal overload с callback; публичный API прежний.

Финальные результаты: .NET 10 - 36 109 утверждений, включая 35 990 чтений; .NET Core 2.2 - 29 207 утверждений, включая 29 088 чтений. Число чтений зависит от планировщика, это не число независимых сценариев. Логи: `work/e01-razor/files10.log`, `files22.log`.

## Published-host

Используется существующий изолированный `work/e0-razor10`. Не удалять исходные материалы E0: сравнение использует его девять успешных HTML-эталонов. Перед прогоном обновить production-копии и обе публикации:

```powershell
& work/e0-razor10/setup.ps1
dotnet publish work/e0-razor10/modern/Probe.csproj -c Release -o work/e0-razor10/published10 --no-restore -p:NuGetAudit=false
dotnet publish work/e0-razor10/legacy/Probe.csproj -c Release -o work/e0-razor10/published22 --no-restore -p:NuGetAudit=false
python tests/RazorPublicationRegression/check-hosts.py
python tests/RazorPublicationRegression/check-imports.py
```

Нужны Python/Pillow, локальные зависимости стенда и свободные loopback-порты 51870/51872/51874. Скрипты изменяют только синтетические шаблоны и изображения в публикациях стенда; процессы завершаются в finally. Imports восстанавливаются в finally. Производственные контроллеры и EF не исполняются: используются прежние тестовые границы E0.

`check-hosts.py` проверяет SHA-256 всех 39 production-копий против оригиналов и source-manifest. Проверяет LF, CRLF, CR, кавычки/backslash (включая буквальное `\n`), Unicode/кириллицу, вложенные условия, Html.Raw и ImageTagHelper. Эталоны сравниваются точно, включая управляющие символы и завершающие переводы строк. Для девяти прежних сценариев отдельно сравнивается полный HTML с E0; не используется нормализация HTML. Также проверяются создание после запуска, обновление/чанки без перезапуска, холодное/повторное чтение и диагностика намеренно ошибочного Razor. Гонка: общий старт 32 писателей и 32 читателей, каждый читатель делает 16 запросов; допустима только полная отправленная версия. HTTP 500 в намеренно ошибочных/отсутствующих views ожидается отдельно от успешных сценариев.

Результаты и ответы E0.1 пишутся в `work/e01-razor`, исходные `results.json` и `evidence` E0 сохраняются. Снимок прежних эталонов - `e0-evidence.json`. Набор imports проверяет обе платформы. Ненулевой exit code означает FAIL или аварийный выход теста.

Прежний `tests/TemplateRegression` также проверен в копии `work/e01-razor/template-regression` на net10.0: 8 неизменных эталонов, независимость замен, 200 параллельных генераций, 4 операции чанков. Его исходный net9.0 запуск не выполнен: локально отсутствует targeting pack 9.0.21; исходный проект не менялся.

## Границы

Блокировка действует внутри одного процесса по полному текстовому пути; симлинки/hardlink и другие процессы не координируются. Windows: MoveFileExW с MOVEFILE_REPLACE_EXISTING, без COPY_ALLOWED, ограниченный повтор ошибок 5/32/33 до 1 секунды. Длительно запрещающий доступ дескриптор даёт исключение с сохранением прежней версии. Linux: File.Replace для существующего файла, File.Move для нового, но Linux здесь NOT TESTED. Атомарная видимость рассчитана на локальную файловую систему с атомарным rename в одном каталоге; crash-durability, сетевые ФС, специальные ACL/атрибуты, длинные пути и сбои cleanup не проверены. Метаданные старого файла не обещаны: публикуется новый inode/файл с правами временного файла.

БД/ФС, rename/delete Template/Chunk и прямые записи product_block не образуют общей транзакции. E0.1 закрывает два адресных дефекта, не всю миграцию и не архитектурный вопрос Runtime Compilation. Основной TargetFramework и зависимости сохранены. Commit/push не выполнялись.
