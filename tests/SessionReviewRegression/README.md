# Регрессии независимого ревью 2.2

Набор запускает реальные SessionStore, AddConnectedUser, Exit, EditUserData, ChangeInitialPassword, SessionExceptionFilter и SQL проекта на runtime ASP.NET Core 2.2.8 / MySQL 8. Настройки локального подключения читает из AGENTS.md в памяти, не из config.json. Пароль не передаётся аргументом и не выводится. Перед изменениями проверяется соединение с существующей `test` на 127.0.0.1:3306.

Безопасность данных: EF работает на одном открытом соединении с собственными TEMPORARY Users/UserTypes/ConnectedUsers/AdminPanelLogs. Они скрывают постоянные одноимённые таблицы только в этом соединении; DROP всегда TEMPORARY. Миграция выполняется на трёх собственных постоянных таблицах с проверенным отсутствующим случайным префиксом `r22_<GUID>_`. В копии SQL за один проход заменяются только имена объектов. В finally удаляются только эти таблицы и процедура; триггер удаляется вместе со своей таблицей. Другие базы, учётные записи и существующие таблицы не меняются. При аварийном завершении процесса проверить остатки конкретного префикса вручную; массовая очистка запрещена. Параллельный запуск набора не предусмотрен.

Пример из корня репозитория (сборку предпочтительно выполнять в отдельной копии без config.json/bin/obj/.vs):

```powershell
dotnet restore tests/SessionReviewRegression --configfile tests/SessionReviewRegression/NuGet.Config -p:NuGetAudit=false -p:RestoreFallbackFolders="$env:USERPROFILE/.nuget/packages"
dotnet run --project tests/SessionReviewRegression --no-restore -- "$PWD"
```

F-01: настоящий HTTPS Kestrel и CookieContainer. Ответ по A задерживается после работы с БД, ответ нового входа B полностью принимается, затем отпускается ответ A. Проверяются финальная cookie B, следующий успешный HTTP-запрос и отказ A. Варианты: заменённый/истёкший токен, старый logout, текущий logout, обычная и первоначальная смены пароля. Отдельно обычный/повторный logout: остаточная отозванная cookie не даёт доступ.

F-02: уникальный индекс TEMPORARY-журнала вызывает реальные MySQL 1062 после commit. Проверяются HTTP 200 входа и профиля, действующая cookie, новый/старый пароль, отзыв, отсутствие повторно ожидающей записи EF и диагностическое событие 2202 без исключения провайдера.

F-03: отказ до DELETE при конфликте имени индекса, дополнительном индексе удаляемого столбца, слишком длинном префиксе IP, функциональном индексе, составном PK, дубликате старого индекса, CHECK, триггере и лишнем внешнем ключе. Сверяются полная CREATE TABLE, все значения строки сессии, пользователь и маркер. Для конфликта имени отдельно проверяется успешный повтор после явного удаления только собственного фикстурного индекса. Положительный сценарий проверяет переход к шести колонкам и повтор без отзыва новой сессии.

F-04: моделируется открытие страницы и один следующий GET журнала через реальную сессионную политику/БД/HTTPS, затем ручной GET. Проверяются LastActionUtc, исключение prefetch, 27 часов моделируемой активности и точная граница IdleTime. Часы внедряются через существующий Func<DateTime>, фиксированного абсолютного срока нет.

Это адресный HTTP-host со служебными маршрутами теста, вызывающими production-методы и фильтр, а не запуск полного Startup/MVC/Razor сайта. Javascript, фактические вкладки браузера и production proxy здесь не проверяются. Тестовый одноразовый сертификат и отключение его проверки существуют только в этом проекте.

Старый AdminSecurityIntegration по-прежнему требует отдельного одноразового MySQL-сервера: на текущей существующей `test` его запускать нельзя. Новый набор не использует его разрушительные фикстуры.
