Для нового решения записывать: ID, дату, статус, выбор, короткую причину и последствия. Изменение предложения на «принято» должно опираться на явное согласование. Совместимость версий проверять заново при реализации.

При дальнейшем планировании учитывать D03. Работы, целесообразные только при переходе на PostgreSQL, отмечать отдельно в PROGRESS.md как «на этап переноса», чтобы не выполнять их дважды. Это не основание откладывать необходимое устранение критического дефекта текущего приложения. Рекомендации по MySQL в AUDIT.md отражают исходный аудит, а не новый целевой стек.
