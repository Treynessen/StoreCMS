# Технические решения

Актуальная очерёдность — D18 с уточнением [D20](#d20); целевой стек — D03. D20 разделяет модернизацию приложения и заключительный перенос существующих данных. Формулировки о следующих задачах в прежних решениях отражают дату принятия: D12 описывает подготовку CSRF до включения проверки по D14; D02 уточнено D04–D07. История решений сохранена.

<a id="d20"></a>
## D20 — перенос существующих данных после разработки и тестирования

**Статус:** принято владельцем. **Дата:** 2026-10-20.

Причина изменения порядка работ — сначала получить работоспособное и полноценно проверенное обновлённое приложение с целевой схемой, затем разрабатывать перенос необходимых существующих данных в эту схему. D03 и D18 не отменяются: цель — .NET 10 / ASP.NET Core 10 / EF Core 10 и PostgreSQL через Npgsql; приоритет критической безопасности и сохранности данных сохраняется.

- После E0 приоритет — модернизация приложения и создание рабочей схемы PostgreSQL. Разработка и тестирование ведутся на отдельной тестовой PostgreSQL с тестовыми данными.
- Сейчас не разрабатывать мигратор, не выполнять пробный перенос существующих данных и не исследовать подробно их содержимое. Совместимость SQL/LINQ, типы, ключи, индексы, ограничения и миграции целевой схемы проверять в ходе модернизации.
- Схема PostgreSQL должна допускать будущий перенос важных данных; полностью повторять старую схему MySQL не требуется.
- После завершения разработки и полноценного тестирования создать отдельную .NET-программу переноса, подключающуюся к MySQL и PostgreSQL через соответствующие провайдеры. Переносить необходимые данные с сохранением важных идентификаторов, связей и целостности.
- При будущем переносе учитывать файлы Storage и ссылки на них; сейчас файлы не переносить.
- Финальный перенос, проверка результатов и переключение на новую систему — отдельный заключительный этап с разрешения пользователя. Отсрочка переноса данных не закрывает дефекты и риски аудита.

Последовательность работ — [PROGRESS.md](PROGRESS.md); границы текущей и целевой архитектуры — [ARCHITECTURE.md](ARCHITECTURE.md).

<a id="d19"></a>
## D19 — адресное совместное чтение генерируемого Razor

**Статус:** реализовано по заданию владельца E0.4 после проверки совместимости. **Дата:** 2026-10-20.

В Razor-списке оборачивать существующие PhysicalFileProvider на прежних позициях через PostConfigure; hosting ContentRootFileProvider/WebRootFileProvider и static files не заменять. Менять только CreateReadStream существующих .cshtml под Views/Templates и Views/Chunks на FileShare.ReadWrite | FileShare.Delete. Imports/ViewStart и прочие файлы сохраняют стандартное чтение; метаданные, DirectoryContents и Watch делегируются исходному provider. Обёртка не владеет его жизненным циклом. Для 2.2 используется RazorViewEngineOptions; проверенный вариант 10 — MvcRazorRuntimeCompilationOptions, без переноса production на 10 в этой задаче.

Основание: E0.3 подтвердил sharing violation и кеширование ошибки; E0.4 проверил контракт, DELETE-дескриптор и опубликованный HTTP на 2.2.8/10.0.13. Это совместимость существующего механизма, не решение о долгосрочной замене obsolete Runtime Compilation. Не расширяет атомарность writer на БД/набор файлов, прямые записи product_block или другие процессы. D03/D18 сохраняются; Linux NOT TESTED.

<a id="d18"></a>
## D18 — приоритет безопасности и сохранности данных, затем миграция

**Статус:** принято владельцем. **Дата:** 2026-10-20.

Приоритет модернизации StoreCMS — устранение критических проблем безопасности и сохранности данных с последующим переходом на .NET 10, EF Core и PostgreSQL/Npgsql. Некритические дефекты, оптимизации памяти и масштабная переработка обработки изображений откладываются, если не являются необходимым условием безопасной миграции. Основание — явное задание владельца об актуализации стратегии.

Последствия:

- D03 сохраняется; D16 и D17 не отменяются.
- F-IMG-03 остаётся открытым; отсрочка не закрывает F-IMG-04/05/06 и другие дефекты.
- Таблица Images и ImageTagHelper пока сохраняются. Отказ от Images не является обязательным условием миграции.
- Перед миграцией необходим аудит совместимости и минимальных условий безопасности. Открытые P1 и риски потери данных требуют оценки; откладывать их автоматически нельзя.
- Каждое существенное изменение должно иметь проверяемые критерии приёмки, включая сохранение существующих возможностей, URL и данных. Работоспособные компоненты не переписывать без технического обоснования.
- После миграции вернуться к некритическим дефектам и оптимизациям; исследования не считать принятыми решениями о реализации.

## Реестр прежних решений

### P04 - переходное Razor Runtime Compilation при миграции (предложено)

**Статус: предложение для утверждения владельцем, не принято. Дата: 2026-10-20.**

«На этапе миграции StoreCMS допускается переходное использование официального Razor Runtime Compilation для .NET 10, несмотря на статус obsolete, поскольку динамическое изменение пользовательских шаблонов является необходимой функцией CMS. Использование ограничивается контролируемым deployment, проверяемым publish-профилем и регрессионными тестами. Долгосрочная замена рассматривается отдельно, без автоматического начала разработки собственного компилятора».

Основание: эксперимент E0 и исправления E0.1; основной StoreCMS остаётся на netcoreapp2.2. Microsoft [пометила Runtime Compilation obsolete](https://learn.microsoft.com/en-us/aspnet/core/breaking-changes/10/razor-runtime-compilation-obsolete?view=aspnetcore-10.0) и не рекомендует для production; предложение требует осознанного утверждения исключения. D03 и D18 не изменены. Исправления writer/CRLF не означают принятия P04 или завершения миграции.

Статусы: **принято** — подтверждено владельцем; **предложено** — обсуждается; **историческое** — поведение кода, не новое одобрение. Дата первоначальных исторических решений неизвестна.
